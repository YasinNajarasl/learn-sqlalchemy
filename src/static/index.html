Relationship rules

slides 24–29

ORM
  • back_populates keeps both sides of a relationship in sync.
  • cascade="all, delete-orphan" removes posts when their user is deleted.
  • link_model is SQLModel's typed association table for many-to-many.
  • selectinload is usually the best default for collections.
  • joinedload is better for many-to-one lookups such as post.author.

Field lab: migrate a real database

After lab 10, switch from a disposable database to a new SQLite file. From the project root, apply the checked-in migration and inspect the revision:

export DATABASE_URL=sqlite:///./migration-practice.db
python -m alembic upgrade head
python -m alembic current

Expect 24b470064191 (head). In a practice copy of the project, add nickname: Optional[str] = Field(default=None) to User in src/models.py. Run:

python -m alembic revision --autogenerate -m "add nickname"
python -m alembic upgrade head
python -m alembic downgrade -1
unset DATABASE_URL

Before upgrading, read the generated revision: does upgrade add a nullable column and does downgrade remove it? Explain why create_all() alone would leave an existing table unchanged.

Common mistakes

slide 39

  • N+1 queries — use eager loading for collections.
  • Forgotten commit — flush can send SQL, but closing an uncommitted session rolls the transaction back.
  • Long-lived Session — keep it per request.
  • Session across threads — Session is not thread-safe.
  • Model change without migration — use Alembic.

Best practices

slide 42

  • Use with Session(engine) or a request dependency.
  • Keep Session lifetime short (per request).
  • Prefer selectinload / joinedload for relationships.
  • Manage schema changes with Alembic, not create_all.
  • Use pool_pre_ping=True and PostgreSQL in production.
  • Test with sqlite:///:memory: or Testcontainers.
  • Use raw SQL only when the ORM is not enough.
